# LoRa LXMF Communicator

Асинхронное консольное приложение для децентрализованного обмена сообщениями и файлами по радиоэфиру (LoRa) и IP-сетям. Проект построен на базе **[Reticulum Network Stack](https://reticulum.network/)** и протокола **[LXMF](https://github.com/markqvist/LXMF)**.

Приложение позволяет развернуть защищенную mesh-сеть, независимую от интернета и сотовой связи, используя доступные LoRa-модули.

## 🌟 Особенности

* **Децентрализация:** Работает без серверов. Устройства (узлы) сами маршрутизируют трафик.
* **Асинхронность:** Ядро написано с использованием `asyncio`, что позволяет приложению не зависать при передаче тяжелых файлов и обработке интерфейса.
* **Оптимизированное хранение:** Метаданные сообщений хранятся в локальной базе SQLite (без раздувания БД тяжелым Base64-контентом).
* **CLI Интерфейс:** Удобный интерфейс командной строки с поддержкой перерисовки и истории ввода.
* **Изоляция:** Полностью докеризированная среда (`stdin_open` + `tty` для корректной работы консоли).

---

## 🏗 Принцип работы

Приложение разделено на логические модули:

1. **`core.py` (Ядро):** Отвечает за инициализацию стека Reticulum (RNS), настройку LXMF-маршрутизатора, прослушивание эфира, асинхронную отправку/прием файлов и работу с БД SQLite (с поддержкой очередей и таймаутов блокировок).
2. **`cli.py` (Интерфейс):** Предоставляет интерактивную консоль для пользователя. Обрабатывает ввод команд, отображает входящие сообщения не прерывая набор текста пользователем.

Вся коммуникация проходит через криптографически защищенный стек **Reticulum**. Каждое сообщение или файл шифруется и доставляется по оптимальному маршруту через доступные интерфейсы (LoRa, WiFi, TCP/UDP).

## 📡 Настройка LoRa (Аппаратная часть)

Для связи по радиоэфиру вам понадобится LoRa-микроконтроллер, прошитый как **RNode**.

### 1. Поддерживаемое оборудование

* **LilyGO TTGO LoRa32 / T-Beam** (рекомендуется)
* **Heltec LoRa32 (V2 / V3)**
* **RAK Wireless (RAK4631)**
* *Любой другой ESP32/NRF52 с чипом SX1262, SX1276 или SX1278.*

### 2. Прошивка RNode

Устройство должно работать на прошивке [RNode Firmware](https://github.com/markqvist/RNode_Firmware).
Для прошивки установите утилиту `rnodeconf` на ваш хост-компьютер:

```bash
pip install rnodeconf
rnodeconf --autoinstall

```

Утилита сама определит подключенную плату, скачает нужную прошивку и установит её. Во время установки укажите параметры вашей сети (например, частоту `868 МГц` или `433 МГц` и ширину канала).

### 3. Настройка Reticulum (`config`)

Reticulum ищет свои настройки в папке `~/.reticulum/config`. Приложению нужно указать, как общаться с прошитым RNode.

Откройте файл конфигурации RNS и добавьте интерфейс (пример для USB-подключения):

```ini
[interfaces]
  [[RNode_LoRa]]
    type = RNodeInterface
    interface_enabled = True
    port = /dev/ttyUSB0
    frequency = 868000000
    bandwidth = 125000
    txpower = 7
    spreadingfactor = 8
    codingrate = 5

```

*Подробная документация по настройке интерфейсов: [RNS Interfaces](https://markqvist.github.io/Reticulum/manual/interfaces.html).*

## 🚀 Установка и запуск (Docker)

Проект поставляется с готовыми `Dockerfile` и `docker-compose.yml`.

### Предварительные требования

* Установленный Docker и Docker Compose.
* Проброшенный USB-порт с LoRa-устройством (или настроенный UDP/TCP интерфейс для связи через интернет/локальную сеть).

### 1. Подготовка конфигурации

Создайте директорию для хранения данных Reticulum и базы данных вне контейнера (чтобы данные не пропадали при перезапуске):

```bash
mkdir -p ./data/reticulum
# Поместите ваш настроенный файл config в ./data/reticulum/config

```

### 2. Сборка и запуск

Убедитесь, что файлы называются `core.py` и `cli.py`. Запустите сборку:

```bash
docker-compose build

```

Так как приложению требуется интерактивный терминал (CLI), запускайте его с привязкой к консоли:

```bash
docker-compose run --rm app

```

*(Флаг `--rm` удалит временный контейнер после выхода, а `run` обеспечит правильный захват STDIN для `cli.py`)*.

## 💻 Использование CLI

После запуска вы попадете во встроенную консоль приложения.

### Основные команды (примерный список)

* `/info` — показать ваш локальный LXMF-адрес (Identity) для передачи другим пользователям.
* `/send` — отправить текстовое сообщение пользователю с указанным адресом.
* `/file` — отправить файл. (Чтение файла происходит асинхронно, не блокируя интерфейс).
* `/history` — просмотреть историю сообщений из локальной SQLite базы данных.
* `/quit` или `Ctrl+C` — безопасное завершение работы приложения с закрытием всех соединений и сохранением БД.

```text
└── data/                 # Смонтированная папка (БД SQLite и конфиги RNS)

```

## 🛠 Известные нюансы и решения

* **Ошибка `database is locked`:** База данных SQLite работает в режиме ожидания (timeout=30), что позволяет безопасно читать/писать из разных потоков (например, при получении сообщения из сети и запросе истории из CLI).
* **Спецсимволы в терминале:** В `cli.py` используются символы `\r\033[K` для очистки строки ввода при асинхронном выводе входящих сообщений. Контейнер должен запускаться с поддержкой TTY.
* **Перегрузка БД:** Сохранение файлов и Base64-вложений в SQLite отключено — в БД (в `db_fields`) сохраняются только метаданные сообщений. Сами файлы сохраняются напрямую на диск.
